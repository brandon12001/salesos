# Call outcomes without scrolling

The user reported having to scroll through company/research context to log a call. Active call/callback tasks now render their existing six outcome controls in a fixed bar above the slim stats footer. Contact/company identity, the current task-specific phone number and one Copy number button remain visible beside those controls. Active-call copying is moved from the scrollable card into this bar; historical review and non-call phone copying keep their inline controls. No Answer and Bad Number remain one-click actions; Connected, Answered, Wrong Person and Skip retain their existing dialogs and logging behaviour. Non-call completion controls remain inline.

Each action is rendered once, bound to the currently displayed task and the existing eligibility/transaction handlers. Historical completed-task review and an empty queue have no active call bar. Mouse double-clicks on the instant No Answer/Bad Number controls ignore the second click, preventing an accidental outcome against the next task when the bar stays in place. Keyboard shortcuts retain their existing behaviour.

A ResizeObserver measures the bottom bar and stats together, reserving the corresponding page space. This responds to viewport width, wrapped button text, task/review transitions and footer size. The last research/context actions remain reachable above the bar. The observer disconnects and removes its CSS variable on unmount. Existing dialogs stay above the bar; Focus toast notifications move above it. Button text wraps rather than clipping at narrow widths.

No sales rules, source data structures, cloud saving contracts, contacts, tasks, activity history, readiness, pipeline stages, reserve settings or XP definitions change. No migration, dependency or external service is added. Tests use fictional records and disposable localhost Auth/Postgres/REST/mail only.

The browser regression checks visible, hit-testable controls at page top and bottom with long research on desktop, tablet, mobile and landscape sizes; reachable bottom content; unclipped labels; notification/modal layering; task identity after navigation; historical/empty states; neutral copying; double-click protection; the actual outcomes of all six controls, and correct clipboard values without any scroll at page top/bottom. It also verifies that changing tasks updates the pinned number and an explicitly selected alternative method is copied instead of the primary number. The existing unit/build and full browser reliability suites remain required before the standing-authorised automatic release. Hosted live-account sign-in remains the user's separate manual check.


## Compact main screen

The full KPI dashboard and repeated mode banners no longer push the prospect down the page. Queue selection stays directly accessible; task navigation uses shorter visible labels with its existing accessible names. Session details & tools expands the full 100-minute KPI calculation, remaining-dial estimate, call-log importer, industry reserve shortcut, mode explanations and recently viewed tasks. Its summary and toolbar retain current minute progress. Power Hour remains available after the card. The company description and call objective precede secondary contact administration and research tools. Narrow queue selectors scroll horizontally within their own row without overflowing the page.

A fictional browser scenario turns on KPI-first calling and Industry Focus together and verifies first-screen task identity and company description at 1920×900, 1366×768, 1024×768 and 390×844; the full purpose panel fits above the pinned bar at laptop/desktop widths. It opens session tools and the call-log importer and checks sales data/settings are unchanged. The existing long-context tests cover copying and every outcome at seven viewport sizes, including 320×568 and landscape. Detailed research can still require scrolling; copying and logging active calls do not. No change to the released 100-minute unlock or replenishment rules.
