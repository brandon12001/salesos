# HMRC discovery reliability

A live, tool-generated sourcing audit on 27 November 2026 reproduced HMRC rejections during fast successive scans and a transient upstream 503 that stopped a page. HMRC documents 60 requests per minute: https://www.uktradeinfo.com/api-documentation/. The finder previously fetched detailed trade and activity even for companies that failed its registry/SIC filters.

The shared HMRC HTTP path now schedules request starts at least 1,250ms apart within a warm worker (48/minute, leaving headroom). Its wait queue is bounded to 30 seconds; it refuses excess queued work. A 403 or 429 starts a 60-second cooldown, cancels pending starts and returns an actionable error with Retry-After. It does not automatically retry those responses. One retry is allowed for a network timeout/reset or 502/503/504 on these free, read-only HMRC requests. There are no retries of Lusha, Brave, GLEIF or paid requests. No deployment protection, identity matching, quality or ownership checks are weakened.

The worker gate is not a distributed quota across independent Vercel workers or other applications using the same egress address. Provider rejections still fail closed. No new database, paid API or infrastructure was added. Failed required lookups never return an advanced scan cursor. Optional activity failure cannot manufacture a trade-frequency score, and provider rejection is surfaced instead of silently becoming missing coverage.

Discovery verifies the registry profile before requesting detailed trade/activity. An out-of-sector, excluded or unverified business remains banked as an unqualified discovery with explicit deferred/unknown detail, without those extra HMRC calls. Company identity, current trade requirements and all senior-role/contact safeguards remain unchanged. Unknown turnover is still unknown; a research score is not proof of the £3m–£30m target or UK treasury control.

Validation includes a fake-clock queue/cooldown test, transient/rejection HTTP contracts, a handler-level rate-error/cursor test, an out-of-sector no-extra-trade-request regression, the existing HMRC/turnover/budget/ESM suites, full build and all automated suites. Live sourcing outputs and contact details stay in private audit files outside Git. A successful live API audit does not prove signed-in hosted UI acceptance; the cloud browser reached the Vercel sign-in gate.
