# Requested callbacks and reserve availability

A missed requested callback is different from first outreach. Focus, Task Queue and Intelligence retain the original person, date/time and reason as **Retry requested callback**. The next attempt is a suggested call two working days later, not a new buyer-agreed appointment. No Answer, gatekeeper and busy/answered-without-conversation preserve this context. They never advance stage, readiness or opportunity classification.

Existing generic retries are recognised read-only through their `retry:<leadId>:<taskId>` lineage and actual missed Call activity. There is no workspace rewrite. Same-person bad-number alternatives/replacements retain context through explicit `sourceActivityIds`. Different contacts, unlinked tasks, successful calls, missing evidence and cycles cannot inherit a callback relationship. A declined conversation creates the existing respectful review instead of an automatic retry.

Due real promises and meetings remain first. A suggested callback retry waits behind a pending actual promise; otherwise Opportunities and Qualified work precede it, and it precedes cold Gold/Standard outreach within the selected industry/work queue. Cold Call Mode still filters calls only. Fresh promises, meaningful conversations, positive-response capture, meetings and invalid contact/lifecycle outcomes clear superseded suggested retries while preserving unrelated promises. Repeated missed attempts create one next callback retry for that contact. Routine email merge never absorbs these callbacks.

## Reserve supply

Batch and individual activation now use the same saved minimum score, ownership, research, contact and suppression checks. Previously, a row showed Activate at a score that the transaction would reject. The reserve now displays its blocking reasons and the count/highest score of otherwise eligible leads below the saved threshold. **Review minimum score** focuses the existing rule; changing it requires an explicit Save activation rules. This never changes research scores or grants ownership.

With Cold Call Mode on, the reserve initially selects **With a usable phone number only**. This filters both row and batch activation; email-only records can be included by turning the filter off. Automatic replenishment remains off unless explicitly enabled. Its active-prospect cap does not prohibit deliberate manual activation. Existing research, opt-outs, CRM holds, reclamation approvals and historical activity remain unchanged.

## Verification and limits

`npm run test:callback-retry` covers core generation/cancellation, legacy generic data, actual history linkage, same-contact number repairs, strict negative identity/evidence cases, warm ranking/future promise gating and pure reserve diagnostics. The fictional production-bundle browser suite checks Legacy, Intelligence and shadow modes, inert Copy, actual No Answer, cloud reload and explicit threshold-change/activation with held and email-only controls.

No schema migration, external API, new paid service or production-data testing. Existing tasks lacking trustworthy callback links cannot safely be relabelled from company notes alone. Protected live-account sign-in and native Word/Outlook sending remain user-manual checks.
